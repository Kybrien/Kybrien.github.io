02 · Design principle

Do the thing.

Primary API means outcomes, not plumbing. A Primary node describes the result you actually want — not the Steamworks callback you would otherwise have gone looking for. Host Game means the lobby exists, the listen server is up, the level is loaded and other players can connect. Join Game means the player is in the game. Install Mod means the mod is usable. Success means the workflow finished.

Get Steam YASP. Pick what you want. Do the thing.

Host Game now means host the game. Wild concept, apparently.

03 · Networking

Steam + Unreal. Actually connected.

Most Steam plugins stop at the lobby and leave you to wire the Unreal side yourself. YASP takes the connection all the way into Unreal's own networking stack — and then gets out of the way.

01Steam LobbyDiscovery, invites, privacy and metadata.
02SteamSocketsSteam transport, no manual address plumbing.
03Unreal NetDriverThe Steam transport becomes a real Unreal connection.
04PlayerController · PlayerState · PawnYour normal Unreal actors, spawned the normal way.
05Normal Unreal replicationRPCs, Character Movement, GameMode server logic.
What YASP does

Steam discovery, invitations and connection setup: creating or finding the lobby, resolving the host, opening the SteamSockets route and travelling the client into the server.

What Unreal does

Everything after that. Replicated Actors, Pawns, Character Movement, RPCs, PlayerControllers, PlayerStates and GameMode server logic behave exactly as they do in a stock Unreal project.

Set Replicates and Replicate Movement on your Character and movement replicates. That is the whole trick.

YASP does not replace Unreal replication with a layer of its own — it connects Steam to the one you already know.

06 · API layers

Primary, Helpers, Advanced, Legacy

A normal game ships entirely inside the Primary API, so that is where you should stay. Below it, nothing is hidden: Helpers hold the presets and shortcuts, the Advanced API keeps every low-level Steamworks primitive available, and the Legacy API keeps older Blueprints compiling. The Primary API got smaller in 1.0 because plumbing moved down a layer — not because capability went away.

Recommended

Primary API

Nodes named after what you are trying to do: 163 of them behind one entry point and eight typed services. This is how you normally use YASP.

Optional

Helpers

Presets, config builders and convenience shortcuts. Useful once you know what you want — never something you have to learn first.

Occasional

Advanced API

Fine Steamworks control for a low-level primitive or a specialised feature that has no high-level workflow. Nothing is hidden from you.

Compatibility

Legacy API

The older lower-level API. It stays in the plugin so existing project Blueprints keep working after an update.

08 · Blueprint

Three nodes, one whole feature

Every chain below comes from the Primary API documentation, and every one of them is a finished outcome rather than a first step. Drag from the service pin, pick your node, wire the result into your UI.

Blueprint

Every Primary node is Blueprint-visible and typed, so you know what you are wiring before you wire it. Pure nodes read state. Immediate nodes act and return a result. Async nodes start a Steam workflow and complete through success and failure outputs.

C++

YASP is a C++ plugin with a Blueprint surface on top, so the same subsystem and typed services are available from code. The exact signatures live in the headers shipped with the release.
